# 递归解压 · 使用说明

> **装在哪**：从 Releases 页面下载 `RecursiveExtract-v1.5.7-win64.exe`，放到任意目录双击即可运行。
> 不用装任何东西（Python / 7-Zip / WinRAR 都不需要）；想挪地方的话整个文件搬走也行（单文件）。
> **当前版本 v1.5.7**（2026-09-22）：两条进度条（总体 + 当前文件）、暂停 / 继续 / 停止、
> 16 路并行槽位进度、窗口按内容自适应、智能解压与覆盖策略，并修掉了一批真机实测的卡顿问题。

## 它干什么

选一个文件夹 → 把里面**所有**压缩包解开（**压缩包里面还有压缩包，也照样一层层解开**）。

- **后缀名不准也没关系**：它看的是文件**内容**（文件头），所以
  - `xxx.7z` 其实是个 tar ✅ 照解
  - 文件根本没有后缀 ✅ 照解
  - 后缀写错、写反 ✅ 照解
- **中文名不乱码**：老式 Windows 压缩包（GBK）的名字也能正确还原
- **支持格式**：zip / 7z / tar / tar.gz / tgz / tar.bz2 / tar.xz / gz / bz2 / xz / zst / iso / cab，
  以及 **rar（含加密的 rar）**
  - rar 走**内置的官方 UnRAR**（RARLAB 的 `UnRAR.exe` 7.30）⇒ **加密的 rar4 / rar5、连文件名也加密的包都能解**，填对密码就行
  - iso / 少数其它格式走 Windows 自带的 `tar.exe`
- **`.exe` 外壳**：有些安装包其实只是个"自解压压缩包"（RAR / 7z / ZIP 外壳）
  ⇒ 也会被试着解开、把里面的真文件取出来。**只读取，绝不会运行那个 exe**
- **加密包**：密码框填一次，**只对需要密码的包生效** —— 没密码的包照常解，不用管它
  - 密码填错**不会留下半成品**（整包回滚，原文件一个字不动）

## 进度条、暂停和继续

解压时界面上有**两条进度条**（和 Bandizip 一样）：

| 进度条 | 看什么 |
|---|---|
| **总体进度**（上面那条，更粗更醒目） | `已完成的包数 / 发现的包数`，后面跟着**已解出多少 MB**。递归解压时"总共有多大"是边走边发现的，所以按包数算才稳定；再加上正在解的那个包的内部比例，进度条会平滑往前爬 |
| **当前文件**（下面那条，细） | 正在解的那个文件 + 它的百分比、速度、**大概还要多久**。拿不到单文件粒度的格式（如 iso / cab）会退回显示"本包进度"；连总大小都不知道时，进度条会来回扫，表示"在干活、但估不出还剩多久" |

运行中主按钮左边多出一个 **「暂停」**：

- 点它就停住（按钮变成 **「继续」**），CPU 基本不占用了，可以先去干别的
- 暂停是**在文件边界生效**的：正在写的那个文件会先写完，然后停住
- 想接着干，再点一下「继续」就行
- ⚠️ **有一种情况停得慢**：**7z 包里如果有个特别大的文件**（几百 MB 那种），要等它解完才停得住
  （7z 格式的限制，程序没法从中间掐断）；zip / rar / 照片包这类小文件多的，一按就停
- **暂停时连外部工具（解 rar / iso / cab 用的那个）也会一起被挂住**，不会在后台偷偷继续写
- **暂停时点「停止」也能立刻收手**：正在解的那个包会整包回滚（半成品清掉），已经解好的包保留
- 没开始解压或已经结束时，暂停按钮是灰的（点不动）

## 三个选项什么意思

### 解压方式

| 选项 | 结果（以 `D:\1.7z`、`D:\2.7z` 为例） |
|---|---|
| **每个压缩包 → 它旁边的同名文件夹**（默认，推荐） | `D:\1\` 和 `D:\2\` |
| 解压到压缩包所在文件夹 | 内容直接铺在 `D:\` 里 |
| 全部解压到同一文件夹 | 都进一个目录；上面留空就自动建 `D:\解压文件26_09_22_0926\` |

> "全部到同一文件夹"时默认勾着「每个压缩包仍单独建一个子文件夹」—— 建议保持勾选，
> 否则不同包里同名文件会互相改名/覆盖。
> 注意：输出文件夹、浏览按钮、这个子文件夹选项，**只有选中「全部解压到同一文件夹」这一档时才可操作**；
> 选另外两档时它们是灰的（那两档用不到这些设置）。

### 高级选项

| 项 | 说明 |
|---|---|
| 同名文件 | `rename` 自动改名保留两份（默认）／`skip` 跳过／`overwrite` 覆盖 |
| 最大嵌套层数 | 默认 5 层，防止"包里套包"无限套娃 |
| 并行解压 | 三档 **高 / 中 / 低**（按 CPU 线程数换算：本机 16 线程 ⇒ 16 / 12 / 8 路），默认「中」。解压是 CPU 活，多路并行实测约快 2 倍（**GPU 帮不上忙**）；单个压缩包本身只能单线程解 |
| 解压成功后删除原压缩包 | 默认**不勾**，勾了会二次确认；**`.exe` 外壳和 Office 文档永远不会被删** |
| 解不开的原包加 `.failed` 标记 | 方便你一眼看出哪些没解开、回头重试 |
| 清理解压产生的空目录 | 只清它自己解压出来的空目录 |
| 生成处理报告 | 结束时在文件夹里生成 `解压报告26_09_22_0926.txt` |
| 智能解压 | 包内只有一个与包同名的文件夹时去掉这层（`A.7z` 里是 `A\文件` ⇒ 直接 `A\文件`） |
| 尝试解开 .exe 外壳中的压缩包 | 默认勾。只读取、**不运行程序**；不想要就取消勾选 |

## 安全方面

- 恶意压缩包常用的**路径穿越**（`..\..\`、绝对路径、符号链接、junction）都会被拒绝，文件不会跑到目标文件夹外面去
- 有**压缩炸弹**防护（限单文件大小、单包总解压量、条目数、压缩比）
- **解压失败不会留半成品**（自动回滚这次写出去的东西）
- 中途点「停止」也是安全的，不会破坏已有文件
- **`.exe` 外壳只当数据读**：程序从不运行、不安装被解开的 exe

## 命令行用法（可选）

```bat
递归解压.exe --cli "D:\下载" --password 1234
递归解压.exe --cli "D:\下载" --layout out_dir --out "E:\解压结果"
```

常用参数：`--layout beside_folder|beside_flat|out_dir|out_dir_flat`、`--out 目录`、`--depth 5`、
`--workers 0(自动)`、`--overwrite rename|skip|overwrite`、`--delete`、`--mark-failed`、`--clean`、
`--no-smart-extract`、`--no-exe`、`--no-report`、`--dry-run`
（退出码：0 = 全成功，2 = 有失败）

## 临时文件（解压过程中产生的）

解压 **7z / rar / iso / cab / AES 加密 zip / 自解压 exe** 时，程序会先在一个临时文件夹里解开，
再逐个校验、搬到该去的地方（这样才不会写穿 junction、也不会静默覆盖你的同名文件）：

- 位置：**目标目录旁边**，名字形如 `.rc-sbx-1234-abcd`（7z 自解压外壳另有一个 `.rc-sbx-7zsfx-…`）
- **正常结束 / 报错 / 你点停止 —— 都会自动删掉**
- 只有进程被**任务管理器强杀**、或**断电**时才会残留
- 残留的会在**下次运行时自动清扫**（按 pid 判断原来那个进程确实没了才删，绝不会误删别的实例正在用的）
- 它不会被当成压缩包扫描（带 `.rc-sbx-` 前缀，直接跳过）

同一个道理，写单个文件时会先用 `.rc-part` 临时名，写完再原子改名 —— 所以中途失败**不会**把你的原文件毁成半截或 0 字节。

## 出问题怎么办

- 日志区会直接说哪个包失败、为什么；同时有一份 `解压报告*.txt` 落在文件夹里
- 中途点「停止」是安全的：正在解的那个包会回滚（半成品清掉），已经解好的包保留
- 想临时腾出电脑，点「暂停」就行 —— 恢复后从原地接着解，不用重来
- 程序设置记在 `%APPDATA%\RecursiveExtract\settings.json`（**密码不保存**，每次要重填）
- **「源文件夹」和「输出目录」不会被记住** —— 每次打开这两栏都是空的（其余选项会记住）。
- ⚠️ **密码会出现在进程命令行里**（Windows 平台特性：同机其它进程在解压期间可以读到）。本程序已把密码从日志、报告、配置文件里排除，但**别在不可信的多用户机器上用它解密码包**。
  这样把软件给别人用、或换台机器用时，不会一打开就露出"上次解压了啥、解到哪去了"
